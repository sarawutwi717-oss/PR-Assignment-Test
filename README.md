
## a. วิธีติดตั้งและรัน

### สิ่งที่ต้องมี

- Git
- Node.js 20.9 ขึ้นไป
- npm จะติดตั้งมาพร้อม Node.js

ไม่ต้องติดตั้ง SQLite Server แยกต่างหาก

### ขั้นตอนสำหรับเครื่องที่เพิ่ง clone โปรเจกต์

1. Clone โปรเจกต์และเข้าโฟลเดอร์ที่มี `package.json`:

   ```bash
   git clone <repository-url>
   cd pr-system
   ```

   หาก clone ไว้แล้ว ให้เปิด Terminal ในโฟลเดอร์ `pr-system` แทน

2. ติดตั้ง dependencies:

   ```bash
   npm install
   ```

3. ตั้งค่า environment สำหรับฐานข้อมูล โดยคัดลอก `.env.example` เป็น `.env` เฉพาะเมื่อยังไม่มี `.env`

   PowerShell:

   ```powershell
   if (-not (Test-Path .env)) { Copy-Item .env.example .env }
   ```

   macOS / Linux / Git Bash:

   ```bash
   test -f .env || cp .env.example .env
   ```

   ค่าเริ่มต้นใช้ SQLite ที่ `prisma/dev.db` ไม่ต้องแก้ไข `.env` หากต้องการใช้ค่านี้

4. สร้างหรืออัปเดต schema และเติมข้อมูลตัวอย่าง:

   ```bash
   npm run db:setup
   ```

5. เริ่ม development server:

   ```bash
   npm run dev
   ```

6. เปิด [http://localhost:3000] กด `Ctrl+C` ใน Terminal เมื่อต้องการหยุด server


`npm run db:setup` ใช้ Prisma migrations และ seed ข้อมูลตัวอย่างเมื่อฐานข้อมูลยังไม่มี PR ส่วน `.env` เป็นทางเลือก: หากไม่มีไฟล์นี้ ระบบจะใช้ `file:./prisma/dev.db` เป็นค่า `DATABASE_URL` โดยอัตโนมัติ

### คำสั่งอื่น

```bash
npm test          # รันทดสอบ
npm run lint      # ตรวจสอบ ESLint
npm run build     # สร้าง production build
npm run start     # รัน production server หลัง build
npm run db:migrate # สร้างและใช้ migration สำหรับ development
npm run db:seed    # เติมข้อมูลตัวอย่างเมื่อฐานข้อมูลยังว่าง
```

## b. วิธีใช้งานเบื้องต้น
เลือก role ที่ต้องการจาก dropdown มุมขวาบน แล้วทำตามขั้นตอนของ role นั้น:

### Requester (ผู้ขอ)
1. เลือก **Requester (ผู้ขอ)** จาก dropdown มุมบนขวา
2. กด **สร้างใบขอซื้อ** แล้วกรอกแผนก ชื่อผู้ขอซื้อ และสินค้าอย่างน้อยหนึ่งรายการ โดยระบุชื่อ จำนวน และราคาต่อหน่วย
3. ตรวจสอบยอดก่อน VAT, VAT 7% และยอดสุทธิที่ระบบคำนวณให้ แล้วกด **บันทึก** เพื่อสร้าง PR สถานะ Draft
4. จากหน้ารายการ เลือกตัวกรองสถานะและเปิด PR ที่ต้องการดูรายละเอียด
5. ใน PR สถานะ Draft สามารถแก้ไขหรือลบได้ เมื่อตรวจสอบข้อมูลเรียบร้อยแล้วกด **ส่งขออนุมัติ** และยืนยันเพื่อเปลี่ยนสถานะเป็น Pending ซึ่งจะไม่สามารถแก้ไขหรือลบได้ระหว่างรอพิจารณา
6. หาก PR ถูกปฏิเสธ (Rejected) ให้เปิด PR แล้วกด **กลับไปแก้ไข (เปิดเป็น Draft)** เพื่อแก้ไขและส่งขออนุมัติใหม่

### Approver (ผู้อนุมัติ)
1. เลือก **Approver (ผู้อนุมัติ)** จาก dropdown มุมบนขวา
2. ในหน้ารายการ เลือกตัวกรอง **PENDING** แล้วเปิด PR ที่ต้องการพิจารณา
3. ตรวจสอบแผนก ผู้ขอซื้อ รายการสินค้า และยอดรวม
4. กด **อนุมัติ** และยืนยันเพื่อเปลี่ยนสถานะเป็น Approved หรือกรอกเหตุผลก่อนกด **ไม่อนุมัติ** เพื่อเปลี่ยนเป็น Rejected

ตัวกรองสถานะ **ทั้งหมด**, **DRAFT**, **PENDING**, **APPROVED** และ **REJECTED** ใช้ดูรายการตามสถานะได้ทั้งสอง role

## d. Assumptions ทุกข้อที่ตัดสินใจเอง
- สกุลเงินเป็นเงินบาท (฿) และคิด VAT 7% จากยอดก่อน VAT จำนวนเงินคำนวณและจัดเก็บเป็นหน่วยสตางค์ โดยราคาต่อหน่วยรับทศนิยมได้ไม่เกิน 2 ตำแหน่ง
- PR ต้องมีแผนก ชื่อผู้ขอซื้อ และสินค้าอย่างน้อย 1 รายการ จำนวนสินค้าต้องเป็นจำนวนเต็มตั้งแต่ 1 ขึ้นไป และราคาต่อหน่วยต้องไม่ติดลบ
- PR ใหม่เริ่มเป็น Draft; Requester แก้ไขหรือลบได้เฉพาะ Draft และส่ง Draft ไป Pending ได้ เมื่อส่งแล้วจะแก้ไขหรือลบไม่ได้จนกว่า Approver จะส่งกลับเป็น Draft
- มีหน้าต่างยืนยันก่อนบันทึก ลบ ส่งขออนุมัติ หรืออนุมัติ เพื่อลดการดำเนินการโดยไม่ตั้งใจ
- Approver(ผู้อนุมัติ) พิจารณา PR สถานะ Pending ได้ โดยอนุมัติเป็น Approved หรือไม่อนุมัติเป็น Rejected ซึ่งต้องระบุเหตุผล
- Requester(ผู้ขอ) เปิดเอกสารที่สถานะ Rejected กลับเป็น Draft เพื่อแก้ไขและส่งใหม่ได้
- บทบาท Requester และ Approver เป็น mock role ที่ผู้ใช้เลือกเอง ไม่มี login หรือการผูกกับผู้ใช้จริง บทบาทที่เลือกเก็บใน `sessionStorage` ของแท็บ browser จึงไม่เหมาะใช้เป็นระบบ authorization สำหรับ production
- เลขที่ PR ที่แสดงใช้รูปแบบ `PR-DDMMYYYY-###` (วัน-เดือน-ปี) และเริ่มลำดับใหม่ในแต่ละวัน ส่วนรหัสภายในใช้ `PR0001`, `PR0002`, ...; รหัสสินค้าใช้ `item-0001`, `item-0002`, ...; รหัสประวัติใช้ `LOG0001`, `LOG0002`, ... ลำดับรหัสภายใน สินค้า และประวัติไม่หมุนกลับเมื่อลบรายการ
- ใช้ SQLite เป็นฐานข้อมูลในเครื่องเพื่อให้ติดตั้งและทดลองได้โดยไม่ต้องตั้งค่า database server เพิ่มเติม และข้อมูลตัวอย่างจะถูกเพิ่มเฉพาะเมื่อยังไม่มี PR ในฐานข้อมูล
- ตาราง `PRActivityLog` เก็บประวัติการสร้าง แก้ไข ลบ และเปลี่ยนสถานะ PR เช่น role ผู้ทำรายการ (`REQUESTER`/`APPROVER`), action, สถานะก่อน/หลัง, เหตุผล Reject (ถ้ามี), เวลา และ snapshots JSON ใน `oldData`/`newData` ค่า snapshot ที่ไม่มีในเหตุการณ์นั้นเป็น `NULL` ประวัติยังคงอยู่หลังลบ PR และอ่านได้จาก `GET /api/pr/{id}/history`
